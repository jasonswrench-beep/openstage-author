## The rules that matter most

All are in `CLAUDE.md`; these are the ones a session trips over:

- **Git identity:** every commit authored and committed as `jasonswrench-beep <324576087+jasonswrench-beep@users.noreply.github.com>`. Check
  `git config user.name` and `user.email` before each commit, and `git log -1 --format='%an <%ae> | %cn <%ce>'` after.
- **No signature lines** in commits, tags, pull requests or release notes: no `Co-Authored-By`, no "Generated with". Read each message back.
- **Releases:** commit everything, tag, then build from the tag; sign only when `git describe --exact-match --tags HEAD` prints the tag and
  `git status --porcelain` prints nothing. A pushed tag never moves.
- **The format:** `docs/format-spec.md` changes in the same commit as code that reads or writes the format; every schema change bumps
  `schemaVersion` and ships a migration (`tools/migrate.py`). The format is **0.52.0**.
- **Accessibility:** every editor feature fully keyboard operable and usable with a screen reader; no keyboard traps; published output WCAG 2.2 AA.
  Say in each summary what a change does to keyboard access, focus or screen-reader output.
- **Licensing:** Apache 2.0; GPL and AGPL are a hard stop; check every dependency's licence; FFmpeg is not used in the product.
- **Writing:** no em dashes in prose for this project. From the security review: no commercial product names in docs, commit messages or
  release notes (name a format such as .docx, or describe hardware by kind), and no personal paths (a user folder) in code, tests or docs.

## Things about this computer that will bite

- **PATH too long.** Command Prompt cannot use a PATH longer than 8,191 characters; with one too long it sees an empty PATH, so double-clicked
  `.bat` files say Python or Node "was not found" and `npm run` fails. On 2026-11-27 Jason's user PATH was cleaned (58 entries for folders that
  no longer existed; backup in Jason's user folder, `PATH-backup-2026-11-27.txt`) and File Explorer was restarted. The cause keeps coming back:
  another session's .NET builds add a `...\scratchpad\...\.dotnet-cli\.dotnet\tools` entry for each new scratch folder (ten more appeared
  the same morning). Setting `DOTNET_ADD_GLOBAL_TOOLS_TO_PATH=false` in that project stops it. If tests that start `cmd` fail with "is not
  recognized", check the PATH length first.
- A session's own shell may also carry the old long PATH. Running node and cargo directly, or building the PATH from the registry in
  PowerShell, works around it.
- **Documents is in OneDrive** on this computer, so example copies are in `OneDrive\Documents\OpenStage Examples`. A copy made before an
  example was changed stays as it was: Jason's copy of Branching demo predates the instruction slide and has to be deleted to see the new one.
- **Two copies of the project.** This one, `C:\Dev\openstage-author`, is the live one. `D:\Documents\OpenStage` is an older clone (it stops at
  the alpha 5 README commit) where the alpha releases were built. Its `speech` folder holds the built speech recogniser (whisper.cpp,
  built 2026-10-18), which `tools/build_installer.py` needs; for 1.0.0 it was copied into this project's `speech` folder (ignored by git)
  instead of running `BUILD SPEECH RECOGNISER.bat`, which downloads the source.
- **Building the installer:** run it with a short PATH (see above), from a clean tree at the tag. An untracked file counts: move it out or
  commit it first.
- Line endings: the working copies are CRLF (`* text=auto`). A Python or `sed` rewrite can turn a file into LF; write with `newline=""`
  and check with `file` before committing.
